# 確認事項と解説は、必ずビジュアルで見せる

たかさんは、確認事項や解説を**ビジュアルで見られる形**で受け取ることを希望している。
チャットに長い文章や箇条書きを並べるのではなく、1枚のページにまとめてリンクを渡す。

## いつ使うか

次のどれかに当てはまったら、必ずビジュアルのページを作る。

- **確認事項**：たかさんに選んでもらう・答えてもらう質問がある（方向性、前提、選択肢など）
- **解説**：仕組み、比較、手順、全体像、調査結果、できる／できないの説明
- **提案**：複数の案を並べて判断してもらう

使わなくてよいのは次の場合だけ。

- 一言で済む返事（「了解です」「できました」など）
- 作業の途中経過の短い報告
- たかさんが「文章でいい」「テキストで」と言ったとき

## 作り方

### 1. 出す場所

使える手段を上から順に選ぶ。

1. Artifact ツールがある環境（Claude Code など）：HTMLを書いて公開し、リンクを渡す
2. claude.ai のチャット：HTMLのアーティファクトとして表示する
3. どちらもない：HTMLファイルを作って渡す。それも無理なら、Mermaid図と表を使ったMarkdownにする

### 2. ページの構成

上から次の順に並べる。全部は要らない。内容に合うものだけ使う。

1. **結論**：最初の2〜3行で「何がわかったか／何を決めてほしいか」
2. **図**：流れ・仕組み・関係は、矢印つきの箱やタイムラインで見せる
3. **表**：比較は表にする。○△×や色付きのラベルで、ひと目で差がわかるようにする
4. **状態**：「確認済み」「未確認」「要対応」などはバッジで示す
5. **確認事項**：選択肢カード（下記）

### 3. 確認事項の出し方（たかさんの基本ルール）

- Yes/Noの一択で聞かない。考えられる道筋を **A・B・C…** の選択肢で出し、最後に必ず「**どれも違う**」を入れる
- おすすめがあれば、その選択肢に「おすすめ」のラベルを付ける
- 各選択肢には、選んだら何が起きるかを1〜2行で書く
- 選択肢はクリックで選べるカードにする。選ぶと下に回答文（例：「Q1：A（〜）」）ができ、「回答をコピー」ボタンで返せるようにする
- 質問は一度に4つまで

### 4. デザイン

- スマホの幅でも崩れないこと。ライト／ダークの両方で読めること
- 色は役割で使い分ける（アクセント1色＋「OK・注意・NG」の意味色）
- 絵文字を見出しの飾りにしない
- 番号は、本当に順番がある内容（手順・時系列）にだけ使う

### 5. チャットの本文

チャットには次だけを書く。ページの中身をチャットに書き写さない。

- ページのリンク
- 2〜3行の要約（何のページか、何を決めてほしいか）

## 日本語のチェック

ページに出す前に、すべての文が自然な日本語か確認する。

- 翻訳調、不自然な語順や助詞、説明口調になっていないか
- 専門用語は、たかさんが普段使う言葉に言い換える（例：「API」はそのままでよいが、「エンドポイント」「ストリーミング」は避ける）
- 一文を短く
